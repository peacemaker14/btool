Generation isolation decision (inspected executable omp/18.20.2)

CLI help exposes --no-tools, --no-extensions, --no-skills, --no-rules, --no-context-files, --no-lsp, --no-title, --no-session, and per-run --config overlays. Executable source embedded in the installed Mach-O was inspected without reading auth token files or making a model request. It assigns --no-tools to toolNames=[] but independently enables MCP via !restrictToolNames && (enableMCP ?? true). No CLI option sets enableMCP=false or restrictToolNames=true.

The executable schema defines disabledProviders as an array, mcp.enableProjectConfig as a boolean, and extensions as an array. disabledProviders filters capability registry providers before loading. Disabling all registered discovery providers would suppress native/imported MCP capability discovery, but is still insufficient: createAgentSession unconditionally calls discoverWatchdogFiles(cwd,agentDir) and discoverAdvisorConfigs(cwd,agentDir), and the WATCHDOG.md/yml loaders search filesystem context outside the no-context-files path. These auxiliary discoveries cannot be disabled completely through the exposed CLI flags/overlay. Consequently btools does not run a coding-agent session on untrusted design inputs.

The supported minimal bridge uses declared @oh-my-pi/pi-ai@18.20.2 and @oh-my-pi/pi-catalog@18.20.2, matching the installed executable. It directly invokes streamSimple with tools:[], toolChoice:'none', a single fixed curated system instruction and only explicitly selected input data. It does not import the coding-agent host, createAgentSession, Settings, tools, plugins, extensions, MCP, skills, context discovery, auxiliary model selection, or shell execution. The auth-broker/discover API and auth.keys.resolver reuse existing account auth; their default value resolver does not execute !command syntax. Auth values are never emitted. Snapshot disk caching is disabled for the per-run child via its environment, without changing global configuration.

The installed executable's models --json --no-extensions supplies exact current model selectors and image capability. Public API exposes only selector/name/provider. CLI JSON is only a display projection: the bridge requires the current SDK's exact getBundledModel(provider,id) descriptor and preserves it intact, including request identity, compatibility policy, endpoint, and transport preferences. It never rebuilds a descriptor from limited CLI fields or borrows another model's route. Unsupported exact descriptors fail explicitly. A per-run SDK session ID and provider-state map preserve the selected model's WebSocket transport support without starting an agent session. There is no retry model chain or silent fallback. Child input/output/time are bounded, source is returned as structured JSON text events, and unsuccessful/cancelled generations never replace the working version.

The published 18.20.2 openai-codex/gpt-6.1-sol descriptor uses the raw wire ID with no requestModelId alias; it declares preferWebsockets:true, useResponsesLite:true, omitMaxOutputTokens:true and current compatibility metadata. No account-entitlement conclusion or undocumented model remapping is inferred from an older SDK's HTTP400 rejection. Provider errors remain visible and do not trigger another model selection.
